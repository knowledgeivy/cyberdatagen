\section{Experimental Configuration}
\label{sec:experiment}

This section specifies the complete experimental configuration, detailing all parameters required to reproduce our evaluation framework. Following the methodology established in Section~\ref{sec:methodology}, we provide concrete values for all design parameters including dataset composition, LLM configurations, prompt templates, classifier hyperparameters, and statistical analysis procedures.

\subsection{Dataset and Sampling Configuration}

\subsubsection{Source Dataset}

We employ the CEAS-08 spam email dataset~\cite{champa2024curated}, comprising 39,154 real-world email samples: 21,842 spam (55.8\%) and 17,312 legitimate emails (44.2\%). This publicly available corpus captures diverse spam tactics and patterns observed in operational email systems, providing sufficient scale for statistical replication while representing realistic spam characteristics.

\subsubsection{Stratified Group Partitioning}

Following the sampling design in Section~\ref{sec:methodology}, we partition the corpus into $R = 20$ independent groups through stratified random sampling. The sample size determination follows from power analysis (Equation 2 in Methodology):

With $R = 20$ groups, we achieve statistical power exceeding 80\% for detecting medium effect sizes (Cohen's $d \geq 0.5$) at significance level $\alpha = 0.05$, assuming typical performance variance $\sigma \approx 0.03$ observed in preliminary experiments. This configuration provides sufficient power for rigorous hypothesis testing while maintaining computational feasibility.

Each group contains $N = 1{,}000$ samples with fixed spam proportion $\rho = 0.1$:
\begin{itemize}
    \item Spam samples: 100 per group
    \item Ham samples: 900 per group
    \item Total across 20 groups: 2,000 spam, 18,000 ham
\end{itemize}

The 10\% spam ratio reflects realistic class imbalance in operational email filtering systems. Stratified sampling ensures representation of diverse spam patterns across all groups while maintaining statistical independence through sampling without replacement.

\subsubsection{Train-Test Split}

We employ an 80-20 train-test split with a fixed held-out test set:
\begin{itemize}
    \item Training: 16 groups (1,600 spam, 14,400 ham) for experimental manipulation
    \item Testing: 4 groups (400 spam, 3,600 ham) held constant across all experiments
\end{itemize}

The test set, established before any experimental manipulation, remains identical across all configurations. This eliminates test set variance as a confounding factor, ensuring performance differences reflect genuine treatment effects rather than evaluation artifacts.

\subsection{Synthetic Data Generation Configuration}

\subsubsection{LLM Models and Parameters}

We employ two state-of-the-art large language models to evaluate robustness across different architectures:

\textbf{Model 1: GPT-4.1-mini} (OpenAI)
\begin{itemize}
    \item API endpoint: \texttt{gpt-4-1106-preview}
    \item Temperature: 0.7 (balanced creativity vs consistency)
    \item Max tokens: 1,000 per generation
    \item Top-p: 1.0 (no nucleus sampling restriction)
    \item Frequency penalty: 0.0
    \item Presence penalty: 0.0
\end{itemize}

\textbf{Model 2: Claude-3.5-Haiku} (Anthropic)
\begin{itemize}
    \item API endpoint: \texttt{claude-3-5-haiku-20241022}
    \item Temperature: 0.7 (matched to GPT-4.1-mini)
    \item Max tokens: 1,000 per generation
    \item Top-p: 1.0
    \item Top-k: Not specified (model default)
\end{itemize}

Both models use identical generation parameters (temperature = 0.7, max tokens = 1,000) to ensure fair comparison. The temperature setting balances between deterministic reproduction (temperature → 0) and creative variation (temperature → 1), enabling diverse synthetic samples while maintaining semantic coherence.

\subsubsection{Prompt Engineering Strategies}

We implement three systematically varied prompt strategies. Each prompt follows a consistent template structure with JSON-formatted output for reliable parsing:

\textbf{Template Structure:}
\begin{verbatim}
You are an expert email content analyzer. Given the
following spam email, generate a semantically similar
but lexically distinct spam variant.

[Strategy-Specific Instructions]

Original Email:
{original_spam_content}

Output Format (JSON):
{
  "subject": "generated subject line",
  "body": "generated email body"
}
\end{verbatim}

\textbf{Strategy-Specific Instructions:}

\textit{Original Strategy:} "Faithfully reproduce the spam characteristics including urgency signals, persuasive elements, and social engineering tactics. Introduce natural lexical variation while maintaining semantic similarity and malicious intent."

\textit{Strong Strategy:} "Amplify spam indicators by emphasizing urgency signals (limited time, immediate action required), persuasive elements (too good to be true offers, authority figures), and social engineering tactics (credential requests, fake notifications). Make the spam characteristics more explicit and prominent."

\textit{Weak Strategy:} "Generate subtle spam with reduced explicit indicators. Create content that appears more legitimate while retaining underlying spam nature. Use professional language and minimize obvious urgency signals, making the spam more difficult to detect."

Complete prompt templates with exact wording are provided in Appendix~\ref{appendix:prompts}.

\subsubsection{Generation Protocol}

For each of the 20 groups and 2 LLM models:
\begin{itemize}
    \item Input: 100 real spam samples per group
    \item Process: Apply each of 3 prompt strategies to each sample
    \item Output: 300 synthetic spam variants per group per model (100 × 3 prompts)
    \item Total generation: 12,000 synthetic samples (20 groups × 2 models × 3 prompts × 100 samples)
\end{itemize}

All generations employ fixed random seeds (\texttt{seed=42}) for reproducibility. Failed generations (parsing errors, length violations) are logged and excluded from analysis, with success rates reported in Appendix~\ref{appendix:generation_stats}.

\subsection{Experimental Track Configurations}

\subsubsection{Track 1: Synthetic-to-Real Detection}

This track evaluates training augmentation effectiveness (RQ1) through systematic variation of synthetic data proportion.

\textbf{Configuration:}
\begin{itemize}
    \item Models: 2 (GPT-4.1-mini, Claude-3.5-Haiku)
    \item Prompt strategies: 3 (Original, Strong, Weak)
    \item Mixing strategy: Cross-group only
    \item Synthetic ratios: 11 levels (0\%, 10\%, 20\%, ..., 100\%)
    \item Classifiers: 1 (SVM with linear kernel)
    \item Groups: 20 independent replications
\end{itemize}

\textbf{Experimental units:} $2 \times 3 \times 1 \times 11 \times 1 \times 20 = 1{,}320$ training-evaluation runs

\textbf{Training composition at ratio $\theta$:}
\begin{itemize}
    \item Ham (fixed): 900 real samples
    \item Spam (variable): $(1-\theta) \times 100$ real + $\theta \times 100$ synthetic
    \item Example ($\theta = 0.5$): 900 ham, 50 real spam, 50 synthetic spam
\end{itemize}

\textbf{Testing composition (fixed):}
\begin{itemize}
    \item Ham: 900 real samples
    \item Spam: 100 real samples
    \item Total: 1,000 samples (10\% spam ratio)
\end{itemize}

\textbf{Strategy justification:} Preliminary experiments comparing within-group and cross-group mixing across 3,300 measurements revealed cross-group consistently outperforms within-group (mean F1: 0.563 vs 0.554, $p < 10^{-6}$, Cohen's $d = 0.13$). Given cross-group's consistent advantage and better alignment with realistic deployment scenarios where precise distribution matching is infeasible, all experiments employ cross-group mixing exclusively.

\subsubsection{Track 2a: Baseline Detection (Real-Data-Only)}

This track evaluates zero-shot AI-spam detection capabilities (RQ2a).

\textbf{Configuration:}
\begin{itemize}
    \item Testing models: 2 (GPT-4.1-mini, Claude-3.5-Haiku)
    \item Prompt strategies: 3 (Original, Strong, Weak)
    \item Training synthetic ratio: 1 level (0\% - pure real baseline)
    \item Classifiers: 2 (SVM, Random Forest)
    \item Groups: 20 independent replications
\end{itemize}

\textbf{Experimental units:} $2 \times 3 \times 1 \times 2 \times 20 = 240$ training-evaluation runs

\textbf{Training composition (fixed):}
\begin{itemize}
    \item Ham: 900 real samples
    \item Spam: 100 real samples (no synthetic exposure)
\end{itemize}

\textbf{Testing composition (varies by condition):}
\begin{itemize}
    \item Ham: 900 real samples
    \item Spam: 100 synthetic samples from target LLM and prompt strategy
\end{itemize}

This configuration establishes defenders' readiness when encountering AI-generated spam without prior training exposure to synthetic data.

\subsubsection{Track 2b: Enhanced Detection (Hybrid-Data)}

This track evaluates cross-model augmentation effectiveness (RQ2b).

\textbf{Configuration:}
\begin{itemize}
    \item Testing models: 2 (GPT-4.1-mini, Claude-3.5-Haiku)
    \item Prompt strategies: 3 (Original, Strong, Weak)
    \item Training synthetic ratios: 3 levels (0\%, 50\%, 100\%)
    \item Classifiers: 2 (SVM, Random Forest)
    \item Groups: 20 independent replications
\end{itemize}

\textbf{Experimental units:} $2 \times 3 \times 3 \times 2 \times 20 = 720$ training-evaluation runs

\textbf{Training composition at ratio $\theta$ (cross-model):}
\begin{itemize}
    \item Ham: 900 real samples
    \item Spam: $(1-\theta) \times 100$ real + $\theta \times 100$ synthetic from \emph{opposite} model
    \item Example (testing GPT-4.1-mini, $\theta=0.5$): train on 50 real + 50 Claude-3.5-Haiku synthetic
\end{itemize}

\textbf{Testing composition (fixed per condition):}
\begin{itemize}
    \item Ham: 900 real samples
    \item Spam: 100 synthetic samples from \emph{target} model (opposite of training)
\end{itemize}

The cross-model design tests whether synthetic data from LLM\_B improves detection of spam from LLM\_A, evaluating whether "fighting fire with fire" strategies enhance defensive capabilities.

\subsubsection{Combined Experimental Scale}

Total experimental units: $1{,}320 + 240 + 720 = 2{,}280$ training-evaluation runs across all tracks, models, strategies, and replications.

\subsection{Classification Models and Hyperparameters}

We employ two architecturally distinct classifiers with hyperparameters optimized through systematic grid search.

\subsubsection{Hyperparameter Optimization}

To eliminate hyperparameter tuning as a confounding factor, we conduct systematic grid search with 5-fold stratified cross-validation on a representative baseline configuration (Group 0, 0\% synthetic, original prompt). F1-score serves as the optimization metric given class imbalance.

\textbf{SVM Grid Search:}
\begin{itemize}
    \item C: \{0.1, 1.0, 10.0\}
    \item Kernel: \{linear, rbf\}
    \item Gamma (for rbf): \{scale, auto\}
\end{itemize}

\textbf{Random Forest Grid Search:}
\begin{itemize}
    \item n\_estimators: \{50, 100, 200\}
    \item max\_depth: \{5, 10, 20, None\}
    \item min\_samples\_split: \{2, 5\}
    \item min\_samples\_leaf: \{1, 2\}
\end{itemize}

\textbf{Key Findings:} Linear kernel outperforms RBF for SVM (F1 = 0.825 vs 0.48-0.61), confirming appropriateness of linear decision boundaries for high-dimensional sparse TF-IDF features. Random Forest shows remarkable hyperparameter robustness (F1 range: 0.886-0.917, < 3\% variation). SVM performance is invariant to C values with linear kernel (all configurations yield F1 = 0.825 ± 0.031). Complete grid search results are in Appendix~\ref{appendix:hyperparameter_grid_search}.

\subsubsection{Final Classifier Configurations}

\textbf{Support Vector Machine (SVM):}
\begin{itemize}
    \item Implementation: \texttt{sklearn.svm.LinearSVC}
    \item C: 1.0 (regularization parameter)
    \item Kernel: linear
    \item Class weight: balanced (handles 10\% imbalance)
    \item Max iterations: 10,000
    \item Random state: 42
\end{itemize}

\textbf{Random Forest (RF):}
\begin{itemize}
    \item Implementation: \texttt{sklearn.ensemble.RandomForestClassifier}
    \item n\_estimators: 100 trees
    \item max\_depth: 10
    \item min\_samples\_split: 5
    \item min\_samples\_leaf: 2
    \item Class weight: balanced
    \item Random state: 42
\end{itemize}

\textbf{Track-specific usage:} Track 1 (Synthetic-to-Real) employs SVM only to focus evaluation on generation quality. Tracks 2a-2b (Detecting AI-Generated Spam) employ both classifiers to assess architectural robustness in cross-model detection scenarios.

\subsection{Feature Representation}

All email texts are transformed to TF-IDF (Term Frequency-Inverse Document Frequency) feature vectors using the following configuration:

\begin{itemize}
    \item Implementation: \texttt{sklearn.feature\_extraction.text.TfidfVectorizer}
    \item max\_features: 10,000 (vocabulary size)
    \item ngram\_range: (1, 2) (unigrams and bigrams)
    \item stop\_words: 'english' (remove common words)
    \item lowercase: True (normalize case)
    \item min\_df: 2 (ignore terms appearing in fewer than 2 documents)
    \item max\_df: 0.95 (ignore terms appearing in > 95\% of documents)
    \item sublinear\_tf: True (apply log scaling to term frequencies)
\end{itemize}

The TF-IDF vectorizer is fit exclusively on training data, with the same transformation applied to test data to prevent information leakage. This configuration captures both word-level semantics (unigrams) and local phrase patterns (bigrams) relevant to spam detection, while limiting dimensionality to 10,000 features for computational efficiency.

\subsection{Statistical Analysis Configuration}

Following the statistical framework established in Section~\ref{sec:methodology}, we employ the following specific procedures and parameters:

\subsubsection{Descriptive Statistics}

For each experimental configuration, we compute across $R = 20$ groups:
\begin{itemize}
    \item Mean: $\bar{x} = \frac{1}{R}\sum_{i=1}^{R} x_i$
    \item Standard deviation: $s = \sqrt{\frac{1}{R-1}\sum_{i=1}^{R}(x_i - \bar{x})^2}$
    \item 95\% confidence intervals: $\bar{x} \pm t_{0.025, 19} \cdot \frac{s}{\sqrt{R}}$ where $t_{0.025, 19} = 2.093$
\end{itemize}

\subsubsection{Hypothesis Testing}

We employ paired t-tests comparing each synthetic ratio against the 0\% baseline (pure real data):
\begin{itemize}
    \item Null hypothesis: $H_0: \mu_{\theta} = \mu_{0}$ (no performance difference)
    \item Alternative: $H_1: \mu_{\theta} \neq \mu_{0}$ (two-tailed test)
    \item Significance level: $\alpha = 0.05$
    \item Degrees of freedom: $df = R - 1 = 19$
\end{itemize}

\textbf{Multiple comparison correction:} Given multiple simultaneous tests (11 ratios × 5 metrics = 55 tests per configuration), we apply Benjamini-Hochberg False Discovery Rate (FDR) correction at $q = 0.05$ to control the expected proportion of false discoveries~\cite{benjamini1995controlling}.

\subsubsection{Effect Size Quantification}

We compute Cohen's $d$ standardized effect sizes to distinguish statistical significance from practical importance:
\begin{equation}
d = \frac{\bar{x}_{\theta} - \bar{x}_0}{s_{\text{pooled}}}, \quad s_{\text{pooled}} = \sqrt{\frac{s_{\theta}^2 + s_0^2}{2}}
\end{equation}

Interpretation follows conventional thresholds:
\begin{itemize}
    \item Negligible: $|d| < 0.2$
    \item Small: $0.2 \leq |d| < 0.5$
    \item Medium: $0.5 \leq |d| < 0.8$
    \item Large: $|d| \geq 0.8$
\end{itemize}

\subsubsection{Performance Degradation Analysis}

We model classification performance as a linear function of synthetic proportion through ordinary least squares regression:
\begin{equation}
\text{Performance}_{\theta} = \beta_0 + \beta_1 \cdot \theta + \epsilon
\end{equation}

The regression slope $\beta_1$ quantifies expected performance change per 1\% increase in synthetic data. $R^2$ values indicate pattern linearity: $R^2 > 0.9$ suggests strong linear relationships enabling extrapolation, while $R^2 < 0.7$ indicates non-linearities requiring empirical validation at specific ratios.

\subsection{Performance Metrics}

We evaluate classifier performance using a comprehensive metrics suite capturing different aspects of detection effectiveness:

\textbf{Primary Metric:}
\begin{itemize}
    \item F1-Score: Harmonic mean of precision and recall, balanced assessment under class imbalance
\end{itemize}

\textbf{Supporting Metrics:}
\begin{itemize}
    \item Accuracy: Overall correctness, $(TP + TN) / (TP + TN + FP + FN)$
    \item Precision: False positive control, $TP / (TP + FP)$
    \item Recall: Detection sensitivity, $TP / (TP + FN)$
    \item AUC-ROC: Threshold-independent discrimination ability
    \item Balanced Accuracy: Class-imbalance robust measure, $\frac{1}{2}(\frac{TP}{TP+FN} + \frac{TN}{TN+FP})$
\end{itemize}

F1-score serves as the primary evaluation metric due to its balanced treatment of precision (false positive control) and recall (false negative control), particularly appropriate given the 10\% spam class imbalance. Complete mathematical definitions are provided in Appendix~\ref{appendix:metrics}.

\subsection{Reproducibility and Quality Control}

\subsubsection{Reproducibility Measures}

All experiments employ fixed random seeds throughout the pipeline:
\begin{itemize}
    \item Data sampling: \texttt{random\_state = 42}
    \item LLM generation: \texttt{seed = 42} (where supported by API)
    \item Classifier training: \texttt{random\_state = 42}
    \item Cross-validation splits: \texttt{random\_state = 42}
\end{itemize}

Complete configuration files, prompt templates, and analysis scripts are version-controlled and documented in our public repository (URL to be provided upon publication).

\subsubsection{Quality Control}

We implement comprehensive quality control for LLM-generated samples:

\textbf{Generation validation:}
\begin{itemize}
    \item \textbf{JSON parsing:} All outputs must parse successfully
    \item \textbf{Length constraints:} $10 \leq \text{tokens} \leq 1{,}000$
    \item \textbf{Completeness:} Both subject and body fields required
    \item \textbf{Language detection:} Verify English language content
\end{itemize}

Failed generations are logged with error codes and excluded from analysis. Generation success rates and failure modes are reported in Appendix~\ref{appendix:generation_stats}.

\textbf{Statistical validation:}
\begin{itemize}
    \item Normality tests: Shapiro-Wilk tests for each group ($p > 0.05$ confirms normality assumption)
    \item Outlier detection: Identify groups with performance $> 3$ standard deviations from mean
    \item Variance homogeneity: Levene's test for equal variances across conditions
\end{itemize}

Violations of statistical assumptions trigger non-parametric alternatives (Wilcoxon signed-rank test for non-normal distributions).
